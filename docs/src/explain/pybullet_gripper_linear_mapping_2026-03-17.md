# PyBullet 夹爪线性映射说明

## 这次改了什么

这次把 PyBullet 仿真夹爪的控制语义整理成了“两层范围”：

- 对外滑条显示与 socket 协议语义：
  `[0.0, 0.1]`
- 仿真内部真实控制范围：
  `[0.0, 0.175]`

对应实现改在：

- [`src/piper_pybullet_sim/slider_arm_gripper.py`](/home/xinger/MyWork/piper_control_demo/src/piper_pybullet_sim/slider_arm_gripper.py)

## 为什么要这样改

之前如果直接把滑条内部范围硬裁成 `[0.0, 0.1]`，PyBullet 里的夹爪控制会不自然，因为 URDF / 仿真内部真正正常工作的范围更接近 `[0.0, 0.175]`。

但如果完全沿用原生 `[0.0, 0.175]`，又会和真实机械臂及外部 `gripper` 协议语义不一致。

所以这次改成了线性映射：

- 显示和协议层保持 `[0.0, 0.1]`
- 仿真内部控制层保持 `[0.0, 0.175]`

## 现在的映射关系

采用的是线性换算：

- 协议/滑条 -> 仿真内部  
  `sim_value = protocol_value * 1.75`
- 仿真内部 -> 协议/滑条  
  `protocol_value = sim_value / 1.75`

因为：

- `0.175 / 0.1 = 1.75`

## 代码里是怎么落的

在 [`slider_arm_gripper.py`](/home/xinger/MyWork/piper_control_demo/src/piper_pybullet_sim/slider_arm_gripper.py) 中：

- `gripper_position` 滑条的显示范围现在是 `[0.0, 0.1]`
- 但映射到 `joint7` / `joint8` 时，使用的比例是：
  - `+1.75`
  - `-1.75`

也就是说，用户拖动到：

- `0.1`

时，仿真内部真正写入的会是：

- `0.175`

这样就同时保住了：

- 对外统一语义
- 仿真内部控制正常

## 影响了什么

### 1. 仿真 UI

PyBullet 里的 `gripper_position` 滑条现在显示为和真实机械臂一致的 `[0.0, 0.1]` 语义。

### 2. 仿真内部控制

内部仍然按更合适的 `[0.0, 0.175]` 控制范围驱动夹爪双指。

### 3. socket 协议

后续通过这套夹爪语义发出的 `gripper` 字段，也更容易和真实机械臂侧保持一致。

## 风险与边界

### 风险 1

这次用的是线性映射，前提是假设：

- 仿真夹爪语义和真实机械臂夹爪语义在这一段里近似线性对应

如果后续实测发现中段仍有明显偏差，再考虑更复杂的非线性映射。

### 风险 2

这层映射目前只明确落实在仿真夹爪控制语义上。后续如果增加新的仿真接收端或回传链路，也应继续沿用同一条映射规则，避免不同模块各自写一套。

## 一句话总结

这次不是简单把 PyBullet 夹爪范围改成 `[0.0, 0.1]`，而是通过 `1.75` 的线性映射，让“对外语义”保持 `[0.0, 0.1]`、同时“仿真内部控制”继续使用更自然的 `[0.0, 0.175]`。
